## 项目价值及已验证能力边界

Arachne 在应用升级或切换正则后端时执行同一组模式 / 输入，检查编译接受、匹配存在、整段文本、整段跨度和数字捕获组文本，输出按用例和适配器顺序稳定排列的差异。黄金预期由使用者提供；发现差异不自动判定上游有错或批准迁移。

2026-10-13 本次 Codex 本地执行 default / JS 检查，各 24 项测试通过；真实 demo 文本与 JSON 均符合已入库快照并重复一致。已观测：五个共享 ASCII 用例无差异；反向引用用例由官方引擎接受并匹配、re-mbt Perl 拒绝，产生一条编译接受差异；两个非 ASCII 探针由本项目 ASCII 适配器主动拒绝，产生两条域限制差异；六个官方引擎 Unicode 用例无差异。详细命令与结果见[本次整改记录](initial-review-2026-10-13.md)。这是自动检查证据，**待韦安良复核**。

`re-mbt` 适配器仅接受 ASCII 模式和输入，不能把主动拒绝解释为整个上游的 Unicode 能力结论。偏移按 MoonBit `StringView` 代码单元归一化；补充平面前缀用例的整段跨度为 `[2, 3)`。现有适配器只返回一次整段匹配与数字捕获组文本，不提供所有匹配、命名组映射或捕获组跨度。Unicode 范围表只生成受上限约束的边界样例，未跨两个引擎验证 Unicode，未证明全输入等价。项目不提供运行超时、沙箱或性能保证。

本次未重跑 native / 显式 wasm-gc，也未执行远端 CI、注册表发布或安装验收；此前环境受限记录见[工程验收记录](acceptance-2026-10-13.md)，不得推广 default / JS 的通过范围。
