# Arachne｜2026 年十月参赛申报书草案

**项目定位：Arachne 是 MoonBit 正则行为契约 / 兼容性测试工具。**
项目目标与定位由人工明确，AI 辅助检查和修改。本文为待项目负责人韦安良复核的申报草案。

**方向**：MoonBit 基础库 / 开发者工具。**仓库**：[wallll-wal6/arachne](https://github.com/wallll-wal6/arachne)。

## 项目解决的问题

应用升级或切换正则依赖时，同一模式和输入可能出现编译接受、匹配结果、跨度或捕获值的变化。Arachne 将应用所需行为表示为可重复执行的契约，在基线与候选适配器之间比较实际结果，输出文本和 JSON 报告，供应用负责人判断差异。

Arachne 不实现正则解析器或匹配引擎，不将公开依赖的算法、语法支持或性能算作本项目成果。

## 本项目实现与公开依赖

| 部分 | 源码可核实的职责 |
| --- | --- |
| 契约与比较 | `contract.mbt` 定义用例、可选黄金预期及跨度断言，校验用例和适配器标识，按适配器复用同一模式的编译结果，比较基线与候选结果 |
| 适配与归一化 | `contract.mbt` 中的官方适配器调用 `@regexp.compile` / `execute`；`rembt_adapter.mbt` 调用 `@rembt.Perl::compile_pat` / `exec_opt`，将后端结果转换为统一观测类型 |
| 报告 | `contract.mbt` 输出文本差异；`json_report.mbt` 提供 JSON v1，包含逐用例结果、差异及基线上下文 |
| Unicode 边界夹具 | `unicode_data.mbt` 包含标注为 Unicode 17.0 的类别范围表及有界样例生成函数；`tools/generate_unicode.mjs` 从 `UnicodeData.txt` 生成范围表。数据用于构造测试输入，不参与正则匹配 |
| 回归与示例 | 单元测试、`examples/migration-fixtures` 和 `tools/verify-demo.mjs` 检查比较规则及两种报告的预期结果 |
| `moonbitlang/regexp@0.3.5` | `moon.mod` 声明的直接公开依赖；[上游源码](https://github.com/moonbitlang/regexp.mbt)提供其正则解析与匹配 |
| `walkzzz/re-mbt@0.1.0` | 另一直接公开依赖；[上游源码](https://github.com/walkzzz/re-mbt)提供其正则解析与匹配。Arachne 仅调用 `re` 包的 Perl 前端 |

本项目实现指仓库内的职责边界，不证明全部代码由人工编写。依赖导入见 `moon.pkg`；解析和匹配实现由独立分发的依赖包提供。本仓库没有将两套依赖的引擎源码纳入自身实现。使用公开 API 不构成共同开发、共同维护或上游贡献的证据，也不能据此将上游维护者列为团队成员。许可及数据来源说明见[第三方说明](../THIRD_PARTY_NOTICES.md)。

## 可复现示例与能力边界

[迁移示例](../examples/demo/README.md)通过真实适配器执行以下夹具；计数依次为用例 / 后端 / 差异：

| 套件 | 预期结果 | 证据范围 |
| --- | --- | --- |
| `shared-ascii` | 7 / 2 / 0 | 请求编号、搜索跨度、未参与捕获、空捕获、多捕获和空整段匹配等选定 ASCII 输入 |
| `syntax-difference` | 1 / 2 / 1 | `^([a-z])\1$` 对 `aa`：官方后端接受并匹配；re-mbt Perl 前端拒绝编译 |
| `adapter-domain` | 2 / 2 / 2 | ASCII 适配器主动拒绝非 ASCII 模式或输入，不代表整个上游缺乏 Unicode 能力 |
| `unicode-official-only` | 8 / 1 / 0 | 官方后端的字面量、补充平面跨度、非 ASCII 大写类别匹配及四个生成边界样例 |

适配器返回一次整段匹配、数字捕获组文本和零起点、右端不包含的 MoonBit `StringView` 代码单元跨度，不返回所有匹配、命名组映射或捕获组跨度。`a` 在 `🦊a` 中的示例跨度为 `[2, 3)`，对应 UTF-16 代码单元。

re-mbt Perl 适配器仅接受 ASCII 模式及输入，因为它调用的上游 API 使用字节偏移。当前 Unicode 示例仅运行官方后端；有界样例不证明完整 Unicode 覆盖或全输入等价。项目不提供运行超时、沙箱或性能保证；编译复用是源码中的行为，不是性能基准结论。

JSON v1 的 `compatible: true` 表示该组夹具未产生差异；两侧共同失败仍可能得到 true，必须检查逐项结果。报告不记录人工批准，差异取舍及最终迁移决定由应用负责人作出。字段与兼容约定见[JSON v1 文档](json-report-v1.md)。

## 开源与 AI 辅助披露

Arachne 源码采用 Apache-2.0；外部引擎与 Unicode 数据各保留其许可及来源。人工已明确项目目标与定位，AI 辅助源码、依赖和文档检查及修改。完整的历史及赛期 AI 使用范围、采纳方式和人工审查情况由项目负责人补充确认，自动检查不表示人工审查完成。

## 正式申报前待负责人复核

- 团队组成、独立维护事实和个人贡献范围。
- 是否对两个上游有实际贡献；如有，分别提供可核验链接、日期与贡献范围。
- 九月原申报与初审意见原文，以及本草案对原意见的覆盖情况。
- 已有成果与赛期新增成果的划分、官方申报字段、赛期与参赛要求。
- Unicode 范围表所用原始输入的版本与来源记录，以及完整 AI 使用披露。
- 本草案的最终采纳、人工审查与正式递交状态。

这些事项不能仅由源码或依赖声明确认，见[披露附表](2026-10-disclosure.md)。
